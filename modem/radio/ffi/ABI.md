ABI version 2 exposes the runtime through `mindone_radio.h`. Build the host static library and run the Rust and C checks with `python3 tests/check.py`. `generate.py` owns `wire.rs`, `convert.rs`, `mindone_radio.h`, `tests/generated.rs`, and `tests/layout.c`; `generate.py --check` checks those files without changing them. The generator requires rustfmt; `RUSTFMT` selects its executable. This crate follows the neighboring crates' direct rustc build convention and has no Cargo or Android build manifest.

Every runtime and batch is a nonzero integer handle. The process registry allocates monotonically increasing identifiers across both kinds and never reuses them. Handles have no pointer interpretation. Creation starts `Runtime` with `Config::production`. All state and PTY work remains on the runtime reactor. Submission is safe to call from multiple Binder threads, subject to the borrowed-memory requirements below. The caller provides invocation IDs; they are echoed unchanged and do not select AIDL response methods. The C++ edge must retain the method, original Binder serial, callback object, and callback generation for each invocation. Distinct requests should have distinct invocation IDs even though the runtime accepts duplicates.

All functions returning int32_t return one of the MR status constants. These statuses describe FFI/enqueue operations, not radio responses. `mr_abi_version` and `mr_layout_count` return zero if their panic guard fails. `mr_create` and `mr_next_batch` initialize their output handles to zero before doing work. ABI version 2 reserves MR_WAIT_FOREVER = UINT32_MAX for an untimed condition-variable wait. Infinite waits drain all batches and return MR_STOPPED with a zero handle once the runtime has finished and drained; mr_stop wakes the runtime and its finishing path wakes readers. Finite waits retain MR_TIMEOUT for empty batches, including after finish. All other signatures and layouts are unchanged. Output payload error numbers are the AIDL RadioError numbers, including OEM_ERROR_1 = 501.

The caller zero-initializes request structures and sets the request kind and its corresponding fields. Inactive fields are ignored. Active Boolean and presence fields must be zero or one. A zero presence flag makes the associated payload inactive, preserving the difference between absence and an empty string, array, or structure. All enum fields are fixed-width integer codes defined in the header, not native Rust enums. MR_RADIO_* codes describe this ABI's state values; the C++ edge explicitly maps them to AIDL RadioState.

Strings are UTF-8 byte spans and can contain embedded NUL bytes. Their lengths exclude no implicit terminator. Arrays are typed pointer/count pairs. A zero-length span accepts a null pointer. Nonempty spans must identify readable, aligned allocations of the declared type, valid for the entire call. Output pointers must identify writable, aligned storage. The caller must not mutate borrowed memory during a call. Null, alignment, integer overflow, length, tag, Boolean, presence and UTF-8 checks do not establish allocation provenance: arbitrary non-null dangling pointers violate the C contract and cannot be made safe with catch_unwind. Input decoding limits each span to 65,536 elements and total copied input to 4 MiB per call. Invalid active payloads are rejected before runtime lookup or submission. Inputs are deeply copied before submission returns.

The batch owns every output structure and nested span. `mr_batch_at` returns a const view valid until `mr_batch_free` on that batch. Copy any needed payload before releasing the batch. Do not access views concurrently with release. Batch handles can be transferred between threads. Free takes the address of a handle, releases its registry entry and sets the handle to zero. A second free, including through a copied stale handle, returns MR_INVALID_HANDLE. Batches are independent of their runtime and can be read and released after runtime destruction. The caller must release every batch.

Stop requests termination and wakes the reactor. Destroy invalidates the runtime handle, stops and joins the reactor, and sets the handle to zero. In-flight calls hold their own runtime references; destroy does not invalidate already returned batches. To retain all accepted request replies on shutdown, call stop, continue draining batches, and only then destroy. The edge must reject deliveries for dead/replaced callback generations itself; the FFI does not own Binder callbacks. Panic guards prevent Rust unwinding into C, but do not recover process aborts, out-of-memory termination, or caller memory violations.

The layout functions describe every boundary struct, including their own descriptor. Returned layout names and offsets have static lifetime. Struct fields and numeric tags form the versioned ABI; incompatible layout or semantic changes require a new ABI version. New core request/value variants cause exhaustive Rust conversion matches to fail compilation until the schema is extended.
